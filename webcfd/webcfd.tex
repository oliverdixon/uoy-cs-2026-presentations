\begin{frame}
    \frametitle{C++? In the browser?}
    \begin{itemize}
        \item \textbf{Sure! Why not?}
        \item \emph{WebAssembly} is an open standard, implemented by all major
            browsers, to run native code inside a web browser.
        \item This means that web applications can be written in any mainstream
            language:
            \begin{itemize}
                \item Rust; Go; C\#
                \item C++; Java; assembly language
                \item \ldots \emph{anything with an LLVM front-end} \ldots
            \end{itemize}
        \item Freed from the shackles of JavaScript!
        \item And we can use all of our existing libraries and frameworks:
            just compile them to WebAssembly.
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{GPU-accelerated graphics? In the browser?}
    \begin{itemize}
        \item \textbf{Sure! Why not?}
        \item \emph{WebGPU} is similarly an open standard, implemented by all
            major browsers, to allow web pages to communicate (more or less)
            directly with the GPU.
        \item Shaders are written in the WebGPU Shader Language (looks like
            Rust) to accelerate compute or rendering tasks with the user's GPU.
        \item Exposes APIs to the browser, so applications (including
            WebAssembly apps) can work with the GPU.
    \end{itemize}
    \vfill\centering%
    \fbox{\parbox[t]{.8\textwidth}{Anyone can write fully functional native
        applications with GPU-accelerated graphics that run \emph{by default} in
        any modern browser!}}
\end{frame}
